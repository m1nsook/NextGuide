# Account Mode add-ons

<Callout kind="info" title="Signed catalog preview">
The Account Mode studio now includes **Add-ons** in the sidebar. Once configured, it can browse current approved **content-only v1** registry releases, filter categories, search publishers and open a full add-on detail view. Listings are verified with the site's pinned Ed25519 key on the server before being shown. **Install, enable, update and uninstall are not implemented.**
</Callout>

## Connect the signed catalog

Set the following environment variables on your persistent Account Mode Next.js server:

<CodeWindow title="Account Mode environment configuration" language="bash" code={"NEXTGUIDE_ADDON_REGISTRY_URL=https://your-approved-registry.example/v1/registry\nNEXTGUIDE_ADDON_REGISTRY_PUBLIC_KEY_B64=YOUR_TRUSTED_BASE64_ENCODED_ED25519_PEM"} />

The Base64 value is the trusted registry's **public** Ed25519 PEM key, encoded as UTF-8 then Base64. Obtain the exact public key through a trusted, independent channel; never accept a signing key merely because an unsigned registry response supplied it. Do not put the registry configuration in a `NEXT_PUBLIC_` variable.

If those variables are missing, the Add-ons page explains that the catalog connection is not configured. If the signature or endpoint is invalid, the server rejects the response; it never falls back to unsigned data. Only a logged-in Account Mode owner can access the discovery API.

## Current and future actions

| Action | Status |
| --- | --- |
| Discover | Search and filter approved content-only releases in Account Mode |
| Inspect | Full detail view with author, signed release, compatibility, license and requested permissions |
| Install | Planned: verify artifact bytes, request permission approval and persist installed state |
| Configure | Planned: store scoped settings and trusted credential handles |
| Enable/disable | Planned: start and stop a reviewed extension safely |
| Update | Planned: permission-diff review and transactional integrity checks |
| Rollback | Planned: restore a previously reviewed, compatible version |
| Uninstall | Planned: remove files safely, with a private-data retention choice |

The existing extension capability broker, isolated runner prototype and signed content archive verifier are foundations. They do not make executable marketplace add-ons safe to install today.

## Security requirements before executable add-ons

Executable add-ons require independent code review, properly signed v2 artifacts, hardened OS sandboxing and resource controls, and browser-frame isolation for custom React components. The private registry service remains separately deployed and is **not** part of this public repository.

Track implementation in [roadmap issue #101](https://github.com/m1nsook/NextGuide/issues/101). To publish a currently supported content add-on, start with [Getting started](/addons/getting-started).
