# Permissions & security

NextGuide's extension API separates **what an add-on requests** from **what a site owner approves**. A manifest is not a sandbox, a code signature is not an execution grant, and an add-on cannot grant itself new privileges.

## The capability model

| Capability | Intended scope |
| --- | --- |
| `docs.pages`, `mdx.blocks` | Contribute documentation content and MDX blocks |
| `ui.components`, `admin.pages` | Display custom UI and dashboard tools |
| `theme.tokens`, `icons.packs`, `i18n.locales` | Appearance and translations |
| `ai.providers`, `auth.providers` | Host-mediated AI and authentication integrations |
| `storage.read`, `storage.write` | Namespaced extension storage |
| `network.fetch` | Controlled host-side outbound requests |
| `server.routes`, `server.jobs` | Future isolated server endpoints and tasks |
| `secrets.read` | Reserved capability; not currently exposed as a broker method |

## Declaring permissions is not approval

<CodeWindow title="Draft v2 manifest capabilities" language="json" code={"{\n  \"schemaVersion\": 2,\n  \"id\": \"acme.search-tools\",\n  \"name\": \"Search Tools\",\n  \"version\": \"1.0.0\",\n  \"category\": \"integration\",\n  \"compatibility\": {\n    \"mode\": \"account\",\n    \"nextguide\": \">=1.0.0 <2.0.0\"\n  },\n  \"permissions\": [\n    \"admin.pages\",\n    \"storage.read\",\n    \"storage.write\"\n  ],\n  \"entrypoints\": {\n    \"server\": \"dist/server.mjs\",\n    \"client\": \"dist/client.js\"\n  }\n}"} />

The current trusted host requires explicit owner approval before activation. The future marketplace must ask the owner again when a newer release requests additional permissions.

## Host-mediated messages

The `nextguide/extensions/runtime` broker binds messages to an already verified add-on identity. Client-supplied IDs cannot switch storage namespaces. Network requests are denied by default. The optional restricted HTTPS host adapter pins vetted public IPv4 DNS results to a TLS connection, rejects redirects and has fixed response limits. It must be configured by the trusted host and never exposed directly to add-on code.

<CodeWindow title="Example broker request" language="json" code={"{\n  \"id\": \"request-1\",\n  \"method\": \"storage.get\",\n  \"params\": {\n    \"key\": \"preferences\"\n  }\n}"} />

<Callout kind="warning" title="Isolation is still required">
The broker is a permission enforcement component, **not** a secure JavaScript sandbox. Executable packages need OS/browser isolation and signed artifact verification before they can run. Neither bare Node worker threads nor in-process `import()` provide the required trust boundary.
</Callout>

Learn more in the [Extension API](/addons/api) and the [security roadmap](https://github.com/m1nsook/NextGuide/issues/101).
