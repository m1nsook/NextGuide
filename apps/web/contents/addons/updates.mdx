# Updates and removal

## Publisher workflow

Every new add-on version requires its own independently reviewed immutable GitHub Release, committed source provenance and signed registry approval.

1. Increase `version` in `nextguide-addon.json`.
2. Commit and push the changed files to the source repository.
3. Open the [NextGuide Publisher GitHub App](https://github.com/apps/nextguide-publisher) and select the repository.
4. Validate and submit the new version for independent review.
5. Wait for the signed registry to contain the approved release.

Do not overwrite existing GitHub Release assets to make a silent change. Create a new version instead.

## Account Mode installation lifecycle

The owner-facing **Add-ons** page can install, enable/disable, update, roll back and uninstall **content-only v1** releases when the site's NextGuide package satisfies their declared compatibility range.

| Action | What happens |
| --- | --- |
| Install | Recheck signed registry, verify exact remote archive and place content in private storage, initially disabled |
| Enable | Recheck latest signed approval and local integrity before marking content enabled |
| Disable | Mark content disabled without deleting settings |
| Update | Recheck the newer reviewed version, then atomically advance the pinned version |
| Rollback | Verify an already stored, still-approved version and restore it in a disabled state |
| Uninstall | Remove the installed record; preserve private add-on settings and historical blobs for recovery |

Owner authentication and same-origin checks apply to every mutation. A concurrent change requires refreshing the page rather than overwriting another update. A revoked or stale release cannot be reactivated or rolled back.

<Callout kind="warning" title="Current milestone boundaries">
The Account Mode site does not yet mount installed Markdown pages into public documentation. Executable add-ons, privileged permissions, secrets, React components and automatic background update checks remain future milestones. Legacy v1 content is never compiled as untrusted MDX.
</Callout>
