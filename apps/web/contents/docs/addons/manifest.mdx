# Create an add-on

Start with [NextGuide-Addons](https://github.com/m1nsook/NextGuide-Addons). Choose **Use this template** to get the manifest, Markdown example, validator and GitHub workflow, or fork it.

## Basic manifest

The manifest is named `nextguide-addon.json`. This simplified example shows the key fields:

```json
{
  "schemaVersion": 1,
  "id": "acme.hello-world",
  "name": "Hello World",
  "summary": "Example documentation pages",
  "description": "An introductory content package for NextGuide.",
  "version": "0.1.0",
  "author": { "name": "Acme" },
  "repository": "https://github.com/acme/hello-world",
  "license": "MIT",
  "category": "content",
  "icon": "icon.png",
  "keywords": ["documentation"],
  "compatibility": { "mode": "account", "nextguide": ">=1.0.0 <2.0.0" },
  "permissions": [],
  "entrypoints": { "content": "content" }
}
```

A schema reference can also be included. See the [complete template and JSON Schema](https://github.com/m1nsook/NextGuide-Addons).

The initial format supports Markdown content and a local PNG publisher icon (`icon.png` in the template). Use a square, transparent logo if possible (recommended 256×256; max 256 KiB). The icon is verified against the immutable Git commit and shown on marketplace cards and detail pages **inside Account Mode admin only**. Unrestricted SVG or remote image URLs are not accepted. Runtime permissions are not supported yet. Custom JavaScript, executable MDX, shell scripts, private tokens and arbitrary hooks are not permitted. AI, themes, OAuth and integrations will gain appropriate extension entrypoints as their APIs are implemented.

## Pack and submit your add-on

The [NextGuide-Addons](https://github.com/m1nsook/NextGuide-Addons) template includes an `ng-addon` script for Bun and Node.js, with no additional npm dependencies.

<CodeWindow title="Validate and create a release archive" language="bash" code="node scripts/validate-addon.mjs" />

<CodeWindow title="Build a .tgz archive" language="bash" code="bun ng-addon pack" />

After committing and pushing the manifest, icon and Markdown to your own public repository, set `GITHUB_TOKEN` or `GH_TOKEN` with **Contents: write** for that repository. The token goes only to GitHub.

<CodeWindow title="Verify source and submit for review" language="bash" code="bun ng-addon publish --registry https://ngapi.m1nsook.com" />

The publisher verifies the exact Git commit, creates a versioned GitHub Release with the `.tgz` and submits its URL, commit and SHA-256 to the registry. It is not approved until the NextGuide owner accepts it in the registry admin dashboard. A Discord webhook can notify the owner when a new add-on or update arrives.

**Availability:** The registry is under development and has not been deployed to that domain yet. Publishing needs a running, configured registry. The add-on package stays on GitHub Releases; NextGuide stores only signed review metadata.

[Learn about publishing and review](/docs/addons/publishing).
