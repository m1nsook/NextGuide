# Create an add-on

Start with [NextGuide-Addons](https://github.com/m1nsook/NextGuide-Addons). Choose **Use this template** to get the manifest, Markdown example, validator and GitHub workflow, or fork it.

## Basic manifest

The manifest is named `nextguide-addon.json`. This simplified example shows the key fields:

```json
{
  "schemaVersion": 1,
  "id": "acme.hello-world",
  "name": "Hello World",
  "summary": "Example documentation pages",
  "description": "An introductory content package for NextGuide.",
  "version": "0.1.0",
  "author": { "name": "Acme" },
  "repository": "https://github.com/acme/hello-world",
  "license": "MIT",
  "category": "content",
  "keywords": ["documentation"],
  "compatibility": { "mode": "account", "nextguide": ">=1.0.0 <2.0.0" },
  "permissions": [],
  "entrypoints": { "content": "content" }
}
```

A schema reference can also be included. See the [complete template and JSON Schema](https://github.com/m1nsook/NextGuide-Addons).

The initial format only supports Markdown content with no runtime permissions. Custom JavaScript, executable MDX, shell scripts, private tokens and arbitrary hooks are not permitted. AI, themes, OAuth and integrations will gain appropriate extension entrypoints as their APIs are implemented.

## Validate before submission

<CodeWindow title="Run local checks" language="bash" code="node scripts/validate-addon.mjs\nnode --test test/validate-addon.test.mjs" />

The template's GitHub workflow repeats these checks on pull requests and releases to the default branch. It does not automatically publish or install an add-on.

Submit a link to your repository and immutable commit SHA with the [official submission form](https://github.com/m1nsook/NextGuide/issues/new?template=submit-your-addon.md). An independent review is required before registry inclusion.
