# Installation

NextGuide is installed into your **existing Next.js application**. It creates the documentation routes, MDX files, navigation, and styling for you. You do not need a separate documentation repository, server, or component registry for Developer Mode.

<Callout kind="info" title="Current release channel">NextGuide is currently published as an npm alpha. Install using the `alpha` tag until a stable release is available. The published alpha may not include every feature documented in the development version of this site. Check `nextguide --version` and the [release notes](https://github.com/m1nsook/NextGuide/releases) when upgrading.</Callout>

## 1. Start with Next.js

You can use an existing project, or create a new one:

<CodeTabs items={[{label:"Bun",code:"bunx create-next-app@latest my-docs\ncd my-docs",language:"bash"},{label:"npm",code:"npx create-next-app@latest my-docs\ncd my-docs",language:"bash"}]} />

Developer Mode supports the App Router and Pages Router, JavaScript and TypeScript, and projects with or without a `src/` directory.

## 2. Install the package

Run the command from your Next.js project root:

<CodeTabs items={[{label:"Bun",code:"bun add nextguide@alpha",language:"bash"},{label:"npm",code:"npm install nextguide@alpha",language:"bash"},{label:"pnpm",code:"pnpm add nextguide@alpha",language:"bash"}]} />

NextGuide is **one npm package**. The application provides its own Next.js and React dependencies; there is no separate installation for MDX, OpenAPI, or the UI components.

## 3. Generate your documentation site

Initialize Developer Mode:

<CodeTabs items={[{label:"Bun",code:"bunx nextguide init --developer",language:"bash"},{label:"npm",code:"npx nextguide init --developer",language:"bash"}]} />

The CLI examines your Next.js project and creates a ready-to-edit documentation site. By default, your pages live under `/docs`, leaving the existing homepage intact.

To see what would be generated **before changing files**:

<CodeWindow title="Preview installation" language="bash" code="bunx nextguide init --developer --dry-run" />

For an unattended setup, specify the location:

<CodeTabs items={[{label:"Documentation under /docs",code:"bunx nextguide init --developer --base-path /docs --yes",language:"bash"},{label:"Documentation as homepage",code:"bunx nextguide init --developer --base-path / --replace-home --yes",language:"bash"}]} />

The `--replace-home` flag explicitly authorizes backing up an existing homepage; it does not silently delete the original file. Use `--router app` or `--router pages` if the project contains both router types.

## 4. Start the application

<CodeWindow title="Start Next.js" language="bash" code="bun run dev" />

Open `/docs` on the address printed by Next.js (or `/` if you selected the homepage). Your documentation source lives in `content/docs/`; the generated project files can be edited like normal application code.

<CodeWindow title="Add your first page" language="bash" code={'bunx nextguide page add guides/installation --title "Installation"'} />

NextGuide creates the MDX file and updates the sidebar metadata for you.

## Already using NextGuide?

**Do not rerun `init`** on an existing documentation site. Update the package, then preview `bunx nextguide upgrade --dry-run`. Adopting updated generated layouts is an explicit `--refresh-generated` operation with backups. See [upgrading safely](/docs/getting-started/upgrading).

## What about Account Mode?

Account Mode is a separate, **unreleased** browser-based setup and editing workflow. It needs an App Router application with a persistent Node.js server. [Learn about Account Mode and its security requirements](/docs/getting-started/account-mode).

For contributors who need to test unreleased source code instead of the published alpha, see the [development instructions](https://github.com/m1nsook/NextGuide/blob/main/CONTRIBUTING.md).
