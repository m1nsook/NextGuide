# Install NextGuide

**The source of truth during development is GitHub `main`, not the old npm alpha.** You can test the current build without copying any repository files or workspace packages into your Next.js application.


## What you get after one install

The Developer Mode initializer creates a **fully designed, working documentation website** with local search, navigation, responsive sidebar, theme controls, breadcrumbs, page actions and table of contents. It automatically registers bundled MDX components and generates a working component gallery—no copying component source or manually wiring a layout. [See the exact generated files](/docs/getting-started/generated-files).

## Existing NextGuide projects

Do **not** initialize again after installing a newer NextGuide package. Instead use `bunx nextguide upgrade --dry-run` followed by `bunx nextguide upgrade`. This preserves existing pages, navigation and project files. [See the safe upgrade guide](/docs/getting-started/upgrading).

## 1. Prepare a Next.js application

Use an existing Next.js project, or create one in a separate folder:

<CodeWindow title="Create a fresh test application" language="bash" code={"bunx create-next-app@latest my-docs\ncd my-docs"} />

NextGuide supports both App Router and Pages Router, in TypeScript and JavaScript projects, with or without `src/`.

## 2. Build a single NextGuide package from GitHub

Open the [NextGuide repository](https://github.com/m1nsook/NextGuide) through GitHub Desktop and pull the latest `main` branch. **Keep this repository in its own folder.**

Open PowerShell in the NextGuide repository root and run:

<CodeWindow title="Create and test a local development package" language="bash" code={"bun install\nbun run pack:dev"} />

This builds the single `nextguide` package, runs its CLI and distribution tests, and creates `nextguide-0.0.1-alpha.2.tgz` in the repository root. It does not publish to npm or upload to GitHub.

If a test or the compiler fails, the packaging command stops instead of giving you an untested archive.

## 3. Install only the packaged dependency in your app

Return to PowerShell in your **separate Next.js application** and install the generated archive using its absolute file path:

<CodeWindow title="Install the GitHub build without copying source" language="bash" code={"bun add \"C:\\path\\to\\NextGuide\\nextguide-0.0.1-alpha.2.tgz\"\nbunx nextguide --version"} />

Replace `C:\path\to\NextGuide` with the actual folder containing the archive. This is a local package installation. Your Next.js project does not need the NextGuide monorepo, build tools, or any `@workspace/*` dependencies.

**Do not use `bun add github:m1nsook/NextGuide`**: the repository root is a workspace, not the publishable package. Do not use `bun add nextguide@alpha` for current-source testing: that tag may contain older code.

## 4. Generate documentation routes and pages

Run these commands from the root of the test application:

<CodeWindow title="Initialize Developer Mode" language="bash" code="bunx nextguide init --developer" />

The initializer now asks whether your docs should appear under **`/docs`** (default, preserving your site's homepage), or at **`/`** (documentation becomes the homepage). If an existing homepage would be replaced, NextGuide asks for confirmation and backs it up instead of deleting it.

For noninteractive use, choose exactly one of these:

<CodeTabs items={[{label:"Under /docs",code:"bunx nextguide init --developer --base-path /docs --yes",language:"powershell"},{label:"As website homepage",code:"bunx nextguide init --developer --base-path / --replace-home --yes",language:"powershell"}]} />

The root option uses `--replace-home` to explicitly permit backing up an existing page; the original is preserved as `.nextguide-backup`. The installer also stores `basePath` in `nextguide.config.json`, which the page-creation command uses for new links.

To preview without writing files, use `bunx nextguide init --developer --dry-run --yes`. If the project has both router types, select `--router app` or `--router pages`. New App Router files avoid the `dynamicParams` export rejected by Next.js Cache Components.

## 5. Start Next.js and test

<CodeWindow title="Run your Next.js development server" language="bash" code="bun run dev" />

Open the selected route on the port reported by Next.js, typically `http://localhost:3000/docs` or `http://localhost:3000/`. You should see the Introduction and Getting started pages.

You can add more pages and update sidebar navigation automatically:

<CodeWindow title="Add another documentation page" language="bash" code={"bunx nextguide page add changelog --title Changelog"} />

Edit `content/docs/index.mdx` to customize the homepage, or [read about adding nested pages](/docs/getting-started/adding-pages).

## Retest after NextGuide changes

Pull `main` in your separate NextGuide source checkout, rerun `bun run pack:dev`, and rerun `bun add "C:\path\to\NextGuide\nextguide-0.0.1-alpha.2.tgz"` in the test application. No source files need to be copied between projects.

## When NextGuide is published

After Account Mode is implemented and tested, the public installation will simply be `bun add nextguide`, followed by `bunx nextguide init --developer`. We are intentionally **not** publishing another npm release yet.

[See every generated file and its purpose](/docs/getting-started/generated-files).

<Callout kind="warning" title="Account Mode is still in development">This installation activates the file-based Developer Mode. Account Mode, the `/setup` ownership token and the `/admin` browser editor are not yet available.</Callout>
