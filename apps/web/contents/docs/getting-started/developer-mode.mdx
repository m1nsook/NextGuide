# Developer Mode

Developer Mode keeps content and configuration **inside your Next.js project**. It is available in the NextGuide CLI and works well for developer tools, libraries and product documentation maintained in Git.

<CodeWindow title="Initialize Developer Mode" language="bash" code="bunx nextguide init --developer" />

The initializer detects your Next.js router and places files in the correct `app/`, `src/app/`, `pages/`, or `src/pages/` folder. It does not require SQLite, a user account, or a hosted NextGuide server.

## Add pages without manually wiring navigation

<CodeWindow title="Create a documentation page" language="bash" code="bunx nextguide page add guides/setup --title Setup" />

This creates the MDX file and updates the relevant `_meta.json` files automatically. Use `--dry-run` to preview the changes or `--json` for scripts. [Read the complete page creation guide](/docs/getting-started/adding-pages).


## Choose a readable default appearance

Pass exactly one of `--light` (default), `--dark` or `--system` when creating a site. The starter supplies accessible, high-contrast accents in blue, red, green, purple, yellow, orange, teal and pink.

<CodeWindow title="Shell" language="bash" code="bunx nextguide init --developer --system --accent:teal" />

The chosen mode and palette are stored in `nextguide.config.json`. Explicit light or dark mode does not change with the operating system's theme.

## Upgrade your existing docs without reinstalling

Use `bunx nextguide upgrade --dry-run` to inspect a legacy configuration, then `bunx nextguide upgrade` to apply it. Existing MDX files and sidebar metadata stay untouched. Updating the generated layout or CSS is an **explicit** `--refresh-generated` operation that creates backups. [Full upgrade guide](/docs/getting-started/upgrading).

## Breadcrumbs and page actions

Newly initialized documentation pages include breadcrumbs and a page action menu. **Copy page** copies the original MDX (including frontmatter), and **Ask ChatGPT** opens a new conversation with a prepared prompt containing the page title and an excerpt. Only the excerpt (up to 2,200 characters) is included in the ChatGPT URL; page text is not sent until you choose this action.

You can also enable **Edit on GitHub** by adding `site.editBase` in `nextguide.config.json`. Point it at the source folder containing your MDX files:

```json
{
  "site": {
    "editBase": "https://github.com/owner/repository/edit/main/content/docs"
  }
}
```

Use your repository URL rather than the placeholder. If `site.editBase` is absent, the edit action stays hidden. For existing NextGuide sites, `nextguide upgrade --refresh-generated` can add these controls, with backups for previously generated files.

## What changes at build time?

Next.js compiles your MDX pages into routes. App Router uses `generateStaticParams`; Pages Router uses `getStaticPaths` and `getStaticProps`. The resulting site can be deployed to Vercel, your own Next.js server, or exported statically when configured for static export.

## Setup location and Next.js compatibility

The initializer asks whether you want documentation under `/docs` or as the website homepage `/`. For scripts, use `--base-path` and `--yes`; use `--replace-home` only if you explicitly want to back up an existing homepage. New App Router routes no longer export the `dynamicParams` option that conflicts with Next.js 16.4's Cache Components feature.

NextGuide resolves every local import it generates, including MDX library code, the project configuration, stylesheets and Pages Router `_app` imports. It prefers the project's existing `@/*` or custom alias when that alias actually covers the target, and uses an accurate relative import otherwise. It never rewrites your TypeScript or JavaScript aliases.

To test a new Next.js stable or canary release, run the **Manual Next.js compatibility and update** workflow from GitHub Actions. It executes only when manually launched, and proposes an update PR only if the operator selects that option. It never merges or publishes automatically. See [upstream Next.js releases](https://github.com/vercel/next.js/releases).

You can also run the same packaged-project smoke tests locally, without Actions:

<CodeWindow title="Local Next.js compatibility tests" language="bash" code="bun run compat:next" />

## Check your installed version

<CodeWindow title="Installed NextGuide version" language="bash" code="bunx nextguide --version" />

This prints the version in the current local package without using the internet.

To compare it against npm's public `latest` release:

<CodeWindow title="Check for NextGuide releases" language="bash" code="bunx nextguide version check" />

Use `--tag alpha` to check the prerelease channel, or `--json` for machine-readable output. NextGuide never upgrades packages automatically; the check only contacts npm when you run it. Until a stable version is published, the registry might not have a `latest` tag.

Our **official NextGuide documentation website** shows its development version in the sidebar. This selector is part of the official website only, and is **not** generated in the sidebars of other projects using Developer Mode.

## GitHub Pages

NextGuide's official documentation uses this file-first architecture and publishes a static Next.js export. GitHub Pages cannot run Account Mode because it has no persistent backend.

## What Developer Mode is not

It does not provide `/setup`, `/admin`, passwords, a database, staff roles, uploads, or editing in the browser. Those belong to **Account Mode**, which is still in development.
