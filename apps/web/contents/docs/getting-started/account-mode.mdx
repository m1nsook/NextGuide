# Account mode

**Status: not implemented.** Account mode will be the default installation when the NextGuide all-in-one package and installer are ready. It is **not** used for the official GitHub Pages documentation.

Account mode needs a persistent Next.js server, a writable data directory, and persistent storage. The planned default is **embedded SQLite**, requiring no separate database server for a basic installation.

## First-run ownership

The server generates a cryptographically random single-use ownership token and prints it only in its console. The user verifies that token in /setup before creating a first owner.

After verification, the owner selects site metadata, language, URL, branding, theme, accent color and body/heading/code fonts with a live browser preview; creates their admin credentials; chooses starter content; and confirms setup.

Verification must check a securely hashed token with expiration and attempt limits. Passwords need a modern password hash such as Argon2id, authentication must be rate-limited, and ownership creation plus token consumption must be **transactional** to prevent duplicate claims. Public ownership setup stays locked after the owner is established.

## Persistent local data

~~~text
.nextguide/
  nextguide.db
  uploads/
  backups/
~~~

This directory must be server-only, excluded from Git and static exports, and kept across deployments. Never place the database below public/ or expose it through Next.js static routes.

## Testing and administration

Authenticated site managers will eventually use /admin to edit MDX pages, navigation, OpenAPI, uploaded assets, and settings. **We will test Account Mode from a complete locally installed NextGuide npm package**, not from the official GitHub Pages build.

For NextGuide's own docs, see [Developer mode](/docs/getting-started/developer-mode). For hosting account-mode sites, see [self-hosting](/docs/deployment/self-hosting).
